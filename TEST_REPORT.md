# Отчет о тестировании LibraryApp

## 1. Объект тестирования

Консольное приложение LibraryApp на C# (.NET 8) предназначено для учета книг в библиотеке. Класс Book описывает книгу (Id, Title, Author, IsAvailable). Класс Library хранит список книг и предоставляет операции AddBook, BorrowBook, ReturnBook и FindBook. Тестировались логика выдачи и возврата книг и обработка граничных случаев.

## 2. Методика тестирования

- ручное тестирование: запуск приложения и проверка сценариев в консоли;
- отладка в Visual Studio: точки останова в методах BorrowBook, ReturnBook, FindBook, пошаговое выполнение (F10, F11), наблюдение за переменными в окнах "Локальные" и "Контрольные значения";
- статический анализ кода: анализаторы компилятора и .NET (AnalysisLevel latest, AnalysisMode Recommended), правила стиля и именования из .editorconfig, просмотр окна "Список ошибок".

Автоматические тесты (unit-тесты) не использовались, поэтому процент покрытия тестами не измерялся.

## 4. Результаты инспекции кода

Предупреждения анализаторов до исправлений:

| Код | Место | Замечание | Исправление |
|-----|-------|-----------|-------------|
| CS8618 | Book.cs, Title | Ненулевое свойство не инициализировано | Инициализация значением string.Empty |
| CS8618 | Book.cs, Author | Ненулевое свойство не инициализировано | Инициализация значением string.Empty |
| CS8603 | Library.cs, FindBook | Возможен возврат null при ненулевом типе результата | Тип результата изменен на Book? |
| IDE1006 | Library.cs, поле Books | Нарушено именование приватных полей | Поле переименовано в _books |
| IDE0044 | Library.cs, поле Books | Поле можно сделать readonly | Добавлен модификатор readonly |

Замечания, найденные при ручной проверке кода:

- в BorrowBook и ReturnBook отсутствовали проверки на null и на состояние IsAvailable: добавлены, повторяющаяся проверка наличия книги вынесена в метод TryGetBook;
- метод Main был длинным и выполнял несколько задач: разбит на методы FillLibrary, RunBasicScenario, RunRepeatedBorrowScenario, RunReturnNotBorrowedScenario, RunMissingBookScenario, RunDuplicateIdScenario, PrintBooks;
- AddBook не проверял аргумент и повторяющийся Id: добавлены ArgumentNullException.ThrowIfNull и InvalidOperationException;
- метод GetBooks отдавал наружу изменяемый список: теперь возвращается IReadOnlyList;
- пустых блоков catch и перехвата всех исключений подряд нет: в Main перехватывается только InvalidOperationException.

После исправлений сборка проходит без предупреждений и ошибок (0 Warning(s), 0 Error(s)).

## 5. Итоги

Все найденные дефекты (D-01 – D-05) исправлены, повторный запуск всех сценариев показывает ожидаемое поведение: некорректные операции завершаются понятным сообщением, состояние книг не искажается. Анализаторы кода не выдают замечаний. Структура кода стала проще: методы короткие и решают одну задачу, дублирование проверок убрано.

Покрытие тестами не измерялось, так как автоматические тесты не писались.

Рекомендации:

- добавить проект unit-тестов (xUnit) для методов Library и измерять покрытие;
- вынести вывод сообщений из класса Library в слой интерфейса, а результат операций возвращать через bool или перечисление;
- добавить сохранение списка книг в файл или базу данных;
- включить режим TreatWarningsAsErrors, чтобы новые предупреждения не попадали в репозиторий.
